# 2026-11-02 视觉安防系统

## 定稿：v28 为最终香烟模型

v28 = **YOLOv8s**（C2f 模块，11.14M 参数），同验证集 mAP50 **0.8510**。
昨晚训的 YOLO26s（v31）只有 **0.8104**，比 v28 低 4 个点。
**结论：这个任务上 v8s 胜 26s**，不要再用"新架构=更强"的假设。

## 今天踩的坑（按严重程度）

1. **训练/推理尺度不匹配 5~7 倍** —— 训练 imgsz768 时香烟 16x26，
   推理 3x3+1024 时 111x183。模型学到的特征用不上，训多少轮都白训。
   修法：两边都往中间靠（训练 960 / 推理 2x2+960 → 2 倍差距）。

2. **`optimizer=auto` 会让 `lr0` 失效** —— ultralytics 强制用 MuSGD 的
   lr=0.01。必须显式 `optimizer=MuSGD` 才能让 lr0=0.004 生效。
   改完必须查 `args.yaml` 确认，别信命令行参数。

3. **mosaic 1.0 + scale 0.5 把刚对齐的尺度又拉回去** —— mosaic 会把 4 张
   拼成一张、目标缩 1/4。远距离小目标必须 mosaic≤0.25、scale≤0.3。

4. **`cigarette_conf` 一个值被用在两处**：既是 pipeline 的送审门槛，
   又是香烟模型的推理 conf（`run_multi.py` 的 `extra_conf`）。
   为了"永不告警"把它设成 9.9 → 连框都不输出。
   正确做法：独立开关 `cigarette_alert: false`。

5. **`_defer` 四个 return False 全被上层写成"裁判不可用"** —— LLM 明明
   120/120 全成功，用户却以为服务挂了。现在带 `_defer_why` 显示真实原因
   （低于门槛/不在送审区间/排队满）。

6. **沙箱代理让 LLM 超时** —— 环境里 `http_proxy=127.0.0.1:动态端口`
   被服务继承，DeepSeek 请求全走代理。启动必须清代理变量，见 `start.bat`。

7. **桌面 `FireMonitor.exe` 跑的是单路 run_watch.py + camera 0** ——
   那颗 640x480 恒为 0 检出，用户一直没看到 cam_1 的画面，所以"怎么改都一样"。

8. **NMS 只算 IOU 漏了"包含"** —— 小框被大框罩住时 IOU 只有 0.2~0.35，
   压不掉，出现"同一支烟两个框"。加包含比（≥0.70 判重复）。

## prompt 的重要教训

**不要写成"看到X就判Y"的清单**。今天因为"必须凑近嘴部"这条硬规则，
把举在额头的香烟判成了 other。改成"位置不是判据，形态和材质才是"，
并明确"你看到的画面优先于这些提示"。
长度从 4171 字压到 1692 字，判定理由反而更像人话（"杯状物边缘模糊是
运动拖影"）。
