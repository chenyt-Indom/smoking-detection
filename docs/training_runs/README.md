| **结果** | P 0.781 · R 0.706 · mAP50 0.7767 · **mAP50-95 0.5260** |

**结论：未超过 v5（差 0.0022），不采用。** 但召回略高（0.706 vs 0.702）。

### 为什么没超过

外部集 `Y-烟雾24000.zip`（24,574 张）只有 smoke 一类标注，用 v5 以 conf=0.03 扫描后：

- `nfire == 0`：21,645 张（88.1%）→ 可作纯烟样本，抽 10,463 张入训
- `nfire >= 1`：2,929 张（11.9%）→ 真实火灾场景但无 fire 标注，**排除**（进了会教模型"火不是目标"）

但无火组抽样约六成是**后期合成的白烟贴图**（室内贴白色棉团、边缘生硬）。模型被教成"白色云雾=烟"，结果是召回略升、精确率下降，净效果 mAP 微降。

ep12 之后 7 轮在 0.524~0.5256 徘徊，这批数据能提供的增量已被榨干。

### 踩过的坑：`optimizer=auto` 会静默吞掉 lr0

ultralytics `BaseTrainer.build_optimizer` 里：

```python
if name == "auto":
    LOGGER.info(f"optimizer: 'optimizer=auto' found, ignoring 'lr0={self.args.lr0}' ...")
    name, lr, momentum = ("MuSGD", 0.01, 0.9) if iterations > 10000 else ("AdamW", lr_fit, 0.9)
    self.args.warmup_bias_lr = 0.0
```

`iterations = 步数 × 轮数`，v7 是 8720×20 = 174,400 > 10,000，于是走 `MuSGD + lr=0.01`。**传 `--lr0 0.004` 完全无效**。

铁证：v5（lr0=0.01）与 v7（lr0=0.004）的 results.csv 里 lr 曲线几乎重合——ep1 都是 0.009999，ep2 是 0.019339 vs 0.019009。

修法（`scripts/train_v4.py` 已支持）：

```bash
--optimizer MuSGD --lr0 0.004 --warmup-bias-lr 0
```

第二个坑：显式指定优化器后不再走 auto 分支，`warmup_bias_lr` 会恢复成默认 **0.1**，对微调太猛，必须一起传 0。

## 瓶颈判断

外部数据这条路已经证明无效。真正卡住的是**分辨率与小目标**：

- 面积 <0.5% 的火框召回仅 **49%**（n=74）
- IoU 阈值从 0.45 放宽到 0.10，召回只涨 9pt → 说明是**纯漏检**，不是框不准
- 74 个最小火框里有 31 个模型连覆盖中心的预测都没吐出

加数据解决不了这个，只能提分辨率或改推理切片策略。
